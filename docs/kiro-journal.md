To actually see Kiro's own elicitation UI we'd need `SEANCE_ALLOW_COMMIT=1` plus `SEANCE_CONFIRM_MODE=elicit` and a willingness to let ENTER reach TK4- (still safe: TK4- only rejects the bogus user id). Left off for this session to stay strictly read-only as instructed.
  Screenshot note: no screenshot captured this pass (CLI/tool-call session, no visible elicitation dialog rendered since the gate blocked first). Worth re-running with commits allowed before the demo recording to capture Kiro's actual confirmation UI.
  Surprise: the gate's ordering — read-only check before confirm-mode dispatch — means `SEANCE_CONFIRM_MODE=elicit` is silently irrelevant whenever `SEANCE_ALLOW_COMMIT=0`. - 2026-11-05: `.kiro/specs/mcp-server/tasks.md` changed
- 2026-11-06 (integrator, merging A and processing its handoffs): Agent A's live runs found a real safety defect that no fake could: on the real TK4- an AID sent from a blank VTAM screen is never answered, and the bridge's `readline()` had no timeout, so the explorer, the agent and the MCP call would all hang while holding the single live session. The bridge now bounds every s3270 command, kills the session on silence, raises `AmbiguousAckError` and never resends; an AID is also never written into a locked keyboard (s3270 would queue it and send it later). Same request exposed that `press_key` forwarded any string to s3270, so a key name was a command-injection path; it is now an allowlist.
  Surprise 1: A's stated cause for the capture-loader failure ("field at the top-left") was wrong. The real culprit was the zero-length field the parser emits for an attribute in the last cell, and fixing it exposed a second latent bug (the loader invented a protected field at offset 0, which would have changed `screen_id` for any capture whose first field is not top-left). Real captures made the fake honest.
  Surprise 2: the ownership check I wrote on day one produced a wall of false "violations" the moment a branch had been merged into main and main merged back (criss-cross history; a three-dot diff then charges main's files to the branch). It now inspects only branch-unique commits.
  Surprise 3: the random-seed half of the merge gate caught a flaky test of mine from P0.6 (a 200 ms Hypothesis deadline on a per-example temp dir). That is the reason the gate runs a fixed seed and a random one.
  Surprise 4 (A): the COBOL-backed stand-in now produces the same `screen_id` as the fake on all five screens, so spirit-map's human-approved key policy and tools apply to the live app unchanged, and exploring the live app yields a map identical to the fake's.
