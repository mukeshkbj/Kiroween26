## A finding worth keeping: the acceptance check now behaves like a careful human
With only B merged (before D-1), step 3's modal showed **NEW premium 3.00** for "Set the premium of policy P0000003 to 300". The old demo model parsed the policy number's digits (`b-only-modal-wrong-premium-3.00.png`). My first version of the check looked only for the string "300" anywhere in the modal. It found "300" in the agent's own text and **approved a premium of 3.00**, so the run failed only at step 4. The check now parses the PREMIUM row of the drawn confirm screen, approves only if OLD/NEW are exactly 250.00 → 300.00, and presses Deny otherwise. Re-run with B only, it refused and **0 commits** were sent. With D-1 merged, the modal shows 300.00 and the check approves. The lesson is the one the UI already teaches: trust the drawn screen, not the agent's words.
